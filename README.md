# Бланки · Проверка работ ОГЭ и ЕГЭ

## Android: отдельный автономный пилот

Ветка `codex/android-offline-preview1` добавляет [исходники и описание Android-приложения](apps/android/README.md). [APK и инструкция](https://github.com/psuren1992-glitch/smart-ocr-lite/releases/tag/android-v0.1.0-preview1) опубликованы отдельным предварительным релизом. Проверка на реальном телефоне ещё не завершена; это не обновление серверной версии. Основная ветка этим выпуском не меняется.

Ниже сохранено описание опубликованного серверного снимка.

Локальный помощник для сбора и проверки экзаменационных работ. Администратор выбирает экзамен (ОГЭ/ЕГЭ) и предмет (математика/русский язык) при загрузке каждой работы. Название и эмблема не привязаны к предмету или классу.

Распознавание пока настроено только для конкретного бланка ОГЭ по математике 2026/27 из файла `9б математика.pdf` (15 страниц; на печатном бланке стоит 2026 год). Для остальных трёх сочетаний сохраняется PDF и выбранный тип работы, но OCR, ключи и оценивание не запускаются: статус «Ожидает настройки шаблона». Это ещё не поддержка распознавания русского языка или ЕГЭ. Нужны образцы соответствующих бланков и отдельная настройка. Учителя пока загружают только текущий математический шаблон; выбор новых направлений доступен координатору.

## Запуск

На текущем компьютере: `run_server_5001.bat`, затем http://127.0.0.1:5001. Запуск использует Waitress и перед обслуживанием запросов создаёт проверенную резервную копию на D:.
Из VS Code открывайте именно эту папку проекта. Подробности запуска и резервирования: [docs/deployment.md](docs/deployment.md). `run_web_5001.bat` и `python webapp.py` оставлены для локальной разработки, без автоматического резервирования.

При первом запуске создайте кабинет координатора на `/setup`: код находится в `data/math9/_access/setup-code.txt`. Задайте собственные логин и пароль (от 12 символов). После регистрации код удаляется, повторное создание администратора закрывается. Старые работы доступны только координатору. Порядок приглашения школ: [docs/accounts.md](docs/accounts.md).

Для отдельной среды (Python 3.11):

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python serve.py --backup-dir D:\BlanksBackups
```

Прямые зависимости закреплены на проверенных здесь версиях; это не полный lock всех транзитивных пакетов. Установка с нуля пока отдельно не проверялась.
Tesseract установлен отдельно; стандартный путь Windows: `C:\Program Files\Tesseract-OCR\tesseract.exe`. Другой путь задаётся переменной `TESSERACT_CMD`. PaddleOCR при первом запуске может загружать модель; на текущем компьютере модель уже закэширована. Сами сканы обрабатываются локально.

## Работа

1. Администратор выбирает экзамен и предмет; затем введите название и класс, загрузите PDF (1–100 страниц, до 80 МБ). Следующие шаги доступны для настроенного шаблона.
2. Готовые бланки появляются по одному. Их можно проверять во время обработки остальных.
3. Сверьте ФИО, вариант и ответы 1–19 с фрагментами скана. Вариант по умолчанию 1; определять вариант по правильным ответам приложение не пытается.
4. Отдельно проверьте нижний блок замен. Предположения OCR не применяются автоматически: перенесите подтверждённый ответ в нужное поле, поставьте отметку проверки блока.
5. Сохраните черновик либо нажмите «Проверено». При изменении проверенного бланка и сохранении черновика статус проверки снимается.
6. При необходимости введите ключ для каждого варианта. Пустые задания не оцениваются; допустимые альтернативы задаются через `|`. Ключ не влияет на распознавание. Без ключа или без ручного подтверждения баллы не показываются.
7. Скачайте CSV-таблицу для Excel. В ней есть все бланки, варианты и статусы проверки. Это число верных коротких ответов, не экзаменационная отметка. Задания 20–25 не входят в обработку.
8. Ненужную работу уберите кнопкой «Удалить» в списке «Ваши работы», затем подтвердите «В корзину». Корзина и восстановление доступны только координатору. Через 72 часа исходный PDF, сканы, ответы и ключи удаляются с диска. Очистка выполняется каждую минуту работающим приложением и при запуске после простоя; восстановление после истечения срока запрещено. Во время распознавания удаление заблокировано. Отдельные резервные копии эта очистка не затрагивает.

План пилота примерно для 30 школ: [docs/school-pilot.md](docs/school-pilot.md). Реализованы учётные записи, школы, персональные приглашения и разграничение доступа. 29.09.2026 включён внешний HTTPS-доступ для проверки входа; анонимный доступ к работам и сканам закрыт. Добавлены Waitress, восстановление очереди и копия при запуске. Это ещё не готовность к массовому пилоту: нужны изоляция обработки, регулярное резервирование и нагрузочная проверка. Контрольная точка: [docs/checkpoint-2026-09-29.md](docs/checkpoint-2026-09-29.md).

## Устройство

- `webapp.py`: загрузка, фоновая последовательная обработка, проверка, ключи, экспорт.
- `core/accounts.py`, `core/account_views.py`: SQLite-база пользователей и школ, приглашения на 48 часов, вход и управление доступом.
- `core/math_form.py`: строгие четыре репера, выравнивание, удаление точек рамки, чтение строк. OCR-модель переиспользуется внутри одного рабочего потока.
- `core/grid_reader.py`: проверка знаков и количества цифр по клеткам, резервное чтение увеличенного по высоте фрагмента. Не использует номер задания или ключ ответов.
- `config/math_2026_2027.json`: координаты единственного поддерживаемого бланка.
- `ui/`: интерфейс проверки и кабинеты учителя/координатора, без внешних CDN и редакторов шаблонов.
- `data/math9/<id>/`: исходный PDF, ключи и результаты. Каждый бланк хранится отдельно; исходное OCR сохраняется в `raw`, ручной ввод в `answers`.
- `data/math9/_access/`: база учётных записей и секрет сессий; включать в защищённую резервную копию вместе с работами, не публиковать и не добавлять в Git.
- `tests/`: быстрые проверки приложения и эталонная ручная транскрипция двух страниц.

Сервер приложения слушает только `127.0.0.1`. OCR пока выполняется в одном процессе с веб-приложением; второй экземпляр с общей папкой данных блокируется. При запуске незавершённая очередь восстанавливается из метаданных, готовые страницы и ручные ответы пропускаются. После ошибки всей работы требуется ручной повтор. Ошибка одной страницы не прерывает остальные: такую страницу нужно проверить вручную или загрузить новый скан. Проверка реестра из 30 школ не является проверкой 30 одновременных загрузок.

## Проверки

```powershell
python -m unittest discover -s tests -v
python scripts/check_ocr.py data/math9/<идентификатор-работы>
```

Второй скрипт предназначен именно для нового тестового PDF. Он сравнивает сохранённый `raw` с ручной транскрипцией страниц 1 и 15, включая пустые ответы и нижние замены, и возвращает ненулевой код при несовпадении. Эталон содержит написанное учеником, а не правильные решения. Качество на двух страницах нельзя переносить на все классы.

OCR пока ошибается в похожих цифрах, запятых и ФИО; каждый бланк требует ручного подтверждения. Следующий этап: проверить обновлённый алгоритм на новой, независимой пачке бланков. Автоматического обучения на правках нет.

### Контроль качества после ручной проверки

Версия `math-grid-v2` от 26.09.2026 сравнивалась с сохранённым исходным OCR на тех же 15 проверенных бланках. Из метрики основной строки исключены 4 поля с нижними заменами и 1 зачёркнутая запись. Среди 116 заполненных сопоставимых полей совпадений стало 94 вместо 84 (81,0% вместо 72,4%). С учётом пустых полей: 258/280 вместо 248/280. Исправлено 10 ошибок, ранее верных полей не испорчено на этой выборке; 22 расхождения остаются. ФИО и замены в эти цифры не входят.

Это набор разработки, а не независимое подтверждение точности. Нижние замены по-прежнему требуют ручной сверки: минус уже находится, но запятая и номер задания могут распознаваться неверно. Новая версия применяется к новым загрузкам; существующие `raw`, `answers` и статусы не перезаписываются.

Локально сохранены обезличенные метки, контрольные суммы исходных страниц и подробный отчёт в `data/math9/experiments/` (не попадают в Git). Скрипт сравнения проверяет контрольные суммы до и после обработки и запрещает записывать отчёт внутрь исходной работы:

```powershell
python scripts/benchmark_ocr.py data/math9/WORK_ID data/math9/experiments/reference-2026-09-26.json data/math9/experiments/benchmark-next.json
```

Имя выходного файла должно быть новым. После дальнейших ручных правок контрольные суммы не совпадут: нужен отдельно пересмотренный эталон, а не отключение проверки. Для других PDF этот эталон не подходит. `scripts/audit_review.py` считает изменения учителя, но их доля не является точностью OCR.

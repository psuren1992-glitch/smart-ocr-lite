# Запуск и HTTPS

Текущая реализация рассчитана на один процесс Windows и Python 3.11. Установка зависимостей: `python -m pip install -r requirements.txt`; Tesseract устанавливается отдельно. OCR-модели могут загружаться при первом запуске. Массовая эксплуатация требует доработок из [school-pilot.md](school-pilot.md).

## Локальный запуск

`python serve.py --backup-dir D:\BlanksBackups` слушает только `127.0.0.1:5001`. Каталог резервирования выбирайте на отдельном диске с ограниченными правами. До обслуживания запросов создаётся ZIP-копия данных с проверкой хешей и целостности SQLite. Копии не зашифрованы, создаются только при запуске, не ежедневно; автоматического удаления архивов нет. Одна копия на том же ПК не защищает от потери всего компьютера.

При восстановлении остановите приложение и OCR, проверьте архив по его manifest.json, восстановите вместе работы и каталог `_access` из `data/` архива. Сохраните предыдущие данные отдельно до проверки результата. Не смешивайте разные версии базы учётных записей и работ; не удаляйте базу для сброса пароля. Очистка корзины не удаляет материалы из резервных копий.

## Внешний тест

В репозитории нет действующего адреса сервера и закрытых данных. `deploy/Caddyfile.portal.example` использует переменные `BLANKS_PUBLIC_HOST` (домен или публичный IPv4 без схемы) и `BLANKS_LAN_IP` (адрес сетевого интерфейса ПК). Задайте их в окружении процесса Caddy. Пример предполагает TCP 80 -> LAN:8080 и TCP 443 -> LAN:8443 на роутере. Правило брандмауэра должно разрешать только программу Caddy, нужный интерфейс и эти TCP-порты. Не используйте DMZ и не открывайте 5001 или 2019.

До публикации создайте координатора локально, задайте сильный пароль, ограничьте права каталога `.secrets`, проверьте стабильность LAN-адреса и маршрутизацию VPN. Установите Caddy из официального релиза с проверкой контрольной суммы; проверенная здесь версия 2.11.4. Его бинарные файлы в Git не включены. Выпуск сертификата требует согласия с условиями удостоверяющего центра; конфигурация использует Let's Encrypt и профиль shortlived для IP-сертификатов. Работающий Caddy продлевает сертификат автоматически, но отказ продления нужно контролировать.

В окне приложения задайте `MATH9_PUBLIC_URL=https://<ваш-адрес>` и запустите `python serve.py --https --backup-dir D:\BlanksBackups`. Не запускайте локальный режим за опубликованным прокси: он не включает Secure-cookie. Дождитесь `Backup verified` и доступности backend. Затем из корня проекта запустите `tools\caddy\caddy.exe run --config deploy/Caddyfile.portal.example --adapter caddyfile` с указанными переменными Caddy. Эта команда публикует приложение, а не диагностическую надпись.

Проверьте сертификат без обхода предупреждений, вход с мобильной сети, запрет анонимного доступа к изображениям/CSV/корзине, изоляцию учителей и школ. Пароли вводятся только на HTTPS-странице, не в сообщениях. Для прекращения внешнего теста остановите Caddy и отключите именно созданные правила проброса. Автозапуск Windows в этой версии не настроен; окна серверов должны оставаться работающими.

Рабочие конфигурации `deploy/Caddyfile.portal`, `deploy/Caddyfile.probe`, локальный firewall-скрипт, HTTPS-launcher и журнал конкретного ПК исключены из Git. Их не перезаписывает публикация исходников.
